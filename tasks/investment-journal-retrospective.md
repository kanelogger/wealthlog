# 投资工作台开发复盘

2026-11-04。记录第六版投资闭环开发、完成度复查和返修中可复用的经验。

## 本次暴露的问题

财务质量处理延伸到了原核算、估值、净资产和存储层。缺最终现金、缓存报价来源、汇率日期及数量单位都需要补充核验，增加了实现与回归范围。大型历史回填又暴露出后台维护与财务读取的冲突。

验收过程中多次准备隔离实例、恢复浏览器空间、编译及清理环境。组件检查、原生测试和桌面操作分散进行，重复扩大回归，仍漏掉侧栏展示、Agent Skill 和待办日期边界。首次完成判断过早，后续复查才补齐这些缺口。

这些记录支持判断主要耗时环节，缺少各环节独立计时，无法精确分摊用时。

## 后续执行约定

| 经验 | 执行方式 | 完成依据 |
| --- | --- | --- |
| 按用户能力验收 | 开工时把每条需求对应到操作入口、可观察结果和证据。复查测试的实际断言。 | 每条要求都有对应结果，未验证项明确列出。 |
| 尽早跑通完整链路 | 先在合成账本跑通起草、确认、关联成交、复盘和发布原则，再扩展边界场景。 | 同一条链路的权限、版本和跨层调用均有实际回读。 |
| 先确定数据可靠性 | 明确缺值、来源、日期、单位和缓存含义，由底层统一提供质量结果，再实现汇总和风险比较。 | 数据不足时保留未知，已核实部分可独立查看。 |
| 结论匹配证据层级 | 分别记录组件回放、原生业务测试、协议调用及桌面操作所验证的行为。 | 每项通过结论能定位到相应层级的证据。 |
| 按影响范围安排回归 | 局部改动先跑相关测试，触及共享核算或协议时扩大范围，交付前集中做一次扩大回归。 | 最终改动受到覆盖，复测有明确的变更或失败依据。 |
| 把收尾纳入交付 | 同时检查界面、Skill、文档、历史数据兼容和验收产物清理。 | 完成前独立检查一次用户能否实际完成任务。 |

资金操作继续使用独立开发实例和合成账本。记录隔离标识及夹具范围，复用同一验收环境，结束时撤销测试凭据并清理本次产物。复用环境前先核实其仍然隔离。
